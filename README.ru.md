# pr-assistant

[English](README.md) | **Русский**

Плагин для Claude Code и Codex с двумя сценариями работы с PR на GitHub. По умолчанию ревьюер выбирается по приложению, из которого вызван плагин: Claude Code запускает Claude, Codex запускает Codex. Выбирать ревьюер при установке или первом запуске не нужно.

- `/pr-assistant:review-requests` — находит открытые PR, где ревью запросили лично у тебя (запросы на команду не считаются), прогоняет по каждому Claude Code `/code-review` (по несколько PR одновременно), связанные PR одной задачи дополнительно проверяет между собой и выводит короткий отчет по задачам и репозиториям с номерами пунктов. Рядом со ссылкой на каждый PR стоит пометка: `👀` — PR стоит прочитать самому (большой или трогает миграции, безопасность, деньги, контракты между сервисами), `⚡` — хватит замечаний. Выбираешь номера — он пишет короткие комментарии и после твоего аппрува публикует их одним ревью на PR. PR без замечаний он предлагает апрувнуть, нужные выбираешь в том же ответе.
- `/pr-assistant:my-prs` — проходит по твоим открытым PR, находит неразрешенные комментарии, на которые ты еще не ответил, вносит правки, с которыми согласен (в отдельном worktree, один коммит на комментарий), и показывает сводку. PR с двумя аппрувами помечает «можно мерджить». После аппрува по каждому PR делает три шага: пушит правки, отправляет все ответы одним ревью (как «Submit review» в UI: ревьюер получает одно уведомление, а не пачку) и перезапрашивает ревью у тех, кто его ждет (кнопка «Re-request review»). Ответы короткие: «Сделал», «Добавил джавадок». Если пуш не прошел, ответы по этому PR не отправляются, чтобы «Сделал» не ушло без правки.

Выше указаны команды Claude Code. В Codex выбирай установленный навык через `$` или `/skills`, например `$review-requests`. В нем первое ревью запускается через встроенный Codex Review; работа со своими PR идет в текущем приложении без отдельного ревьюера. В обоих отчетах есть ссылки на PR. Плагин отвечает на твоем языке, комментарии пишет на языке обсуждения PR.

## Без аппрува ничего не уходит в GitHub

Все, что пишет в GitHub (комментарии, ответы, `git push`), собирается в план. План получает код из 6 символов, вычисленный из его содержимого. Хук приложения требует, чтобы последнее сообщение было ровно `ok <КОД>`, и записывает одноразовое подтверждение для сессии и плана. `post.py` проверяет его до любой отправки:

```
Чтобы отправить ровно это, ответь: ok 039CD8
> ok 039CD8
```

- Ответы «да» или «давай» не принимаются, нужен именно код. Если план поменяли после аппрува, меняется и код, и отправка блокируется.
- Пока идет сессия pr-assistant, прямые `gh pr comment/review/merge`, `gh api` с POST/PATCH/PUT/DELETE, GraphQL-мутации и `git push` запрещены.
- Хук отвечает `deny`, а такое решение действует и в режиме `bypassPermissions`.
- В коммитах, ответах и комментариях нет следов ассистента: ни `Co-Authored-By`, ни «Generated with Claude», ни упоминаний Claude или ИИ. Коммит с такой строкой хук отклоняет.
- Другие сессии хук не трогает. Если хуки не подключены или им не выдано доверие, проверка при запуске сообщает об этом, а `post.py` отказывается отправлять план.
- Комментарии публикуются ревью `COMMENT`; изменения плагин не запрашивает. Approve он ставит только PR без замечаний, только если ты выбрал его в плане и только если с ревью в PR не появилось новых коммитов. Треды он не резолвит: это решает ревьюер.

Ограничение: хук проверяет текст команд. Он защищает от случайной отправки, а не от модели, которая целенаправленно ищет обход. Например, он не остановит свой скрипт, который сам вызывает `gh`. Скиллы прямо запрещают так делать.

## Где лежат файлы

| Что | Где |
|---|---|
| Клоны репозиториев | папка, которую плагин спросит при первом запуске |
| Worktree для PR | `<папка клонов>/.pr-worktrees/<repo>-<N>` |
| Результаты ревью, планы, состояние хука | `~/.cache/pr-assistant/` (`PR_ASSISTANT_STATE_DIR`) |

При первом запуске плагин спрашивает, где лежат твои репозитории, и запоминает ответ в `~/.config/pr-assistant/config.json`. Если нужный репозиторий там уже склонирован (`<папка>/<repo>` или `<папка>/<owner>/<repo>`, и `origin` указывает на тот же репозиторий GitHub), плагин работает с этим клоном. Если нет, клонирует его туда сам. Папку можно поменять командой `config.py set repos_dir <path>` или переменной `PR_ASSISTANT_REPOS_DIR` в `~/.claude/settings.json`:

```json
{ "env": { "PR_ASSISTANT_REPOS_DIR": "/path/to/repos" } }
```

Твою рабочую копию плагин не трогает: не переключает ветки и не касается незакоммиченных изменений. В клоне он только делает `fetch` и добавляет worktree. Ревью идет в отдельном worktree на голове PR. Правки к своим PR делаются в worktree на ветке `pr-assistant/<N>` и пушатся в ветку PR fast-forward, без `--force`.

## Как устроено ревью

По умолчанию действует `reviewer=auto`. Хуки передают имя текущего приложения и id сессии, навыки добавляют их к каждому вызову скриптов. Выбор происходит при каждом запуске: одной установкой можно пользоваться из обоих приложений. Порядок CLI в PATH на выбор не влияет. Отсутствие CLI или исчерпание лимита не переключает плагин на другого провайдера.

- Claude запускает `claude -p "/code-review <effort> <base>...<head>"` в worktree с разрешенными инструментами чтения и без MCP-серверов.
- Codex запускает `codex exec review --base <base>` на проверяемом HEAD. У процесса read-only sandbox, запрет повышения прав, отключенный веб-поиск; пользовательские настройки и правила, плагины, приложения и конфигурация MCP исключены из процесса ревью. Используется модель Codex CLI по умолчанию, если не задана `codex_model`; модель текущего чата не наследуется.
- Оба процесса получают окружение без переменных GitHub-токенов и пустой каталог конфигурации `gh`. Сбор PR и подготовка worktree используют твою обычную авторизацию GitHub.

Адаптеры возвращают единый формат результата. Ошибка, пустой или незавершенный ответ не считаются ревью без замечаний. Ключ кэша включает провайдера, настройку модели, effort, версию CLI, адаптера и промпта, полный репозиторий и SHA обеих границ диапазона. Старый кэш Claude не подхватывается.

В вызове навыка можно указать `low`, `medium` (по умолчанию) или `high`. Одновременно идут 2 ревью; `jobs=N` меняет это число, максимум 4. Авторизация и оплата зависят от выбранного CLI. При исчерпании лимита новые ревью не запускаются, уже идущие завершаются, а отчет показывает оставшуюся работу.

Чтобы переопределить автовыбор, попроси ассистента поменять ревьюер или выполни из этой репы:

```bash
python3 scripts/config.py set reviewer codex  # или claude
python3 scripts/config.py set reviewer auto  # снова выбирать по приложению
python3 scripts/config.py set codex_model <model-id>
python3 scripts/config.py set claude_model <model-id>
```

`PR_ASSISTANT_REVIEWER` имеет приоритет над сохраненной настройкой. `PR_ASSISTANT_CODEX_MODEL` и `PR_ASSISTANT_CLAUDE_MODEL` переопределяют модели. При прямом запуске из терминала укажи ревьюер явно или задай `PR_ASSISTANT_HOST=claude|codex`. При обычном вызове навыка вручную это делать не нужно.

## Повторное ревью

Перед каждым ревью плагин смотрит, что уже сказано в PR, и выбирает режим:

- ты этот PR еще не комментировал — обычное ревью;
- ты его уже ревьюил и после этого появились коммиты — ревьюятся только изменения после твоего последнего ревью, а в отчет попадают только подтвержденные блокеры 🔴. Если после твоего ревью в ветку влили `main` или историю переписали, ревьюится весь PR, но фильтр остается тем же;
- новых коммитов с твоего ревью нет или автор еще не ответил на какой-то твой тред — ревью не запускается, PR попадает в список пропущенных с причиной. Тред, на который автор ответил, считается закрытым, даже если его не зарезолвили.

Находка, которая уже есть в любом комментарии к PR (твоем или чужом, в закрытом треде или открытом), в отчет не попадает. Так плагин не повторяет сказанное и не заводит бесконечные круги ревью с новыми мелочами. Пропущенный PR можно проверить принудительно: «перепроверь #65».

## Связанные PR

Одна задача часто задевает несколько репозиториев. PR считаются одной задачей, если у них общий ключ тикета в заголовке или ветке (`PROJ-1234`), одинаковое имя ветки (кроме `main`, `develop`, `release/*` и подобных) или один PR ссылается на другой в описании. В отчете такие PR идут одним блоком.

После отдельных ревью запускается read-only проход по группе (`cross-review.sh`). Он проверяет контракты продюсера и консьюмера, миграции против entity и DAO, имена конфигов, версии общей библиотеки и порядок деплоя. Оба адаптера получают диффы файлами и пути к полным worktree. Claude читает их инструментами без shell, Codex — через read-only sandbox. Кэш группы учитывает настройки ревьюера и base/head SHA каждого PR.

## Установка

Нужны `gh` (с `gh auth login`), `git`, Python 3.9+ и авторизованный CLI выбранного ревьюера. Поддержка Codex рассчитана на CLI 0.167.0 или новее. Оба CLI нужны только для использования обоих ревьюеров.

В Claude Code:

```
/plugin marketplace add Ixxxeon/pr-assistant
/plugin install pr-assistant@pr-assistant
```

Для разработки плагин можно подключить из локальной папки: `/plugin marketplace add /path/to/pr-assistant`.

Для Codex зарегистрируй эту локальную репу и установи плагин:

```bash
codex plugin marketplace add /path/to/pr-assistant
codex plugin add pr-assistant@pr-assistant
```

После публикации этой версии источником marketplace также может быть `Ixxxeon/pr-assistant`. Начни новую сессию. Проверь и подтверди доверие к хукам через `/hooks` или Settings > Hooks в приложении. Codex требует этот шаг: сама установка хуки не активирует. При первом вызове навык проверит оба хука и нужный CLI, затем использует сохраненную папку клонов или спросит ее один раз. Вопроса о выборе ревьюера не будет.

Устанавливай весь плагин: одним навыкам не хватит скриптов и хуков аппрува. Если после обновления Codex пометит измененные хуки как недоверенные, их нужно проверить снова. Документация: [хуки Codex](https://learn.chatgpt.com/docs/hooks), [упаковка плагинов](https://developers.openai.com/plugins/build/plugins).

Если у тебя установлен скилл `writing-plainly`, комментарии проходят через него: так они получаются короче и без канцелярита. Без него плагин тоже работает.

## Структура

```
.claude-plugin/        манифесты Claude и marketplace
.codex-plugin/         манифест Codex
.agents/plugins/       marketplace Codex
hooks/                 хуки сессии, сообщений и инструментов для обоих приложений
skills/review-requests SKILL.md первой команды
skills/my-prs          SKILL.md второй команды
scripts/
  list-review-requests.sh  PR, где ревью запрошено лично у тебя
  list-my-prs.sh           твои открытые PR
  pr-status.py             аппрувы, готовность к мерджу, треды без ответа
  prepare-worktree.sh      клон + worktree (review: detached, own: ветка pr-assistant/<N>)
  group-prs.py             группировка PR по задаче
  review-batch.py          параллельный прогон ревью и проверок групп
  review-history.py        что уже сказано в PR, режим ревью
  review-pr.sh             worktree + ревью + кэш одного PR
  run-code-review.sh       запуск выбранного ревьюера
  cross-review.sh          read-only проверка группы PR между собой
  reviewer.py              автовыбор, запуск процесса, идентификатор кэша
  reviewers/               адаптеры Claude и Codex, общий промпт проверки группы
  doctor.py                проверка приложения, CLI и хуков аппрува
  approval.py              одноразовые подтверждения сессии и плана
  config.py                папка клонов: чтение, запись, поиск клона
  locked.py                блокировка клона репозитория на время fetch/worktree
  plan.py                  план записей в GitHub и код аппрува
  post.py                  отправка одобренного плана
  guard.py                 хук-предохранитель
```
