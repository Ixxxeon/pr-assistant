# pr-assistant

[English](README.md) | **Русский**

Плагин Claude Code с двумя командами для работы с PR на GitHub:

- `/pr-assistant:review-requests` — находит открытые PR, где ревью запросили лично у тебя (запросы на команду не считаются), прогоняет по каждому Claude Code `/code-review` (по несколько PR одновременно), связанные PR одной задачи дополнительно проверяет между собой и выводит короткий отчёт по задачам и репозиториям с номерами пунктов. Рядом со ссылкой на каждый PR стоит пометка: `👀` — PR стоит прочитать самому (большой или трогает миграции, безопасность, деньги, контракты между сервисами), `⚡` — хватит замечаний. Выбираешь номера — он пишет короткие комментарии и после твоего аппрува публикует их одним ревью на PR. PR без замечаний он предлагает апрувнуть, нужные выбираешь в том же ответе.
- `/pr-assistant:my-prs` — проходит по твоим открытым PR, находит неразрешённые комментарии, на которые ты ещё не ответил, вносит правки, с которыми согласен (в отдельном worktree, один коммит на комментарий), и показывает сводку. PR с двумя аппрувами помечает «можно мерджить». После аппрува по каждому PR делает три шага: пушит правки, отправляет все ответы одним ревью (как «Submit review» в UI: ревьюер получает одно уведомление, а не пачку) и перезапрашивает ревью у тех, кто его ждёт (кнопка «Re-request review»). Ответы короткие: «Сделал», «Добавил джавадок». Если пуш не прошёл, ответы по этому PR не отправляются, чтобы «Сделал» не ушло без правки.

В обоих отчётах есть ссылки на PR. Плагин отвечает на том языке, на котором ты пишешь Claude, а комментарии в PR пишет на языке обсуждения PR.

## Без аппрува ничего не уходит в GitHub

Всё, что пишет в GitHub (комментарии, ответы, `git push`), собирается в план. План получает код из 6 символов, вычисленный из его содержимого. Отправка идёт только через `post.py`, и хук Claude Code пропускает её, только если в твоём последнем сообщении есть `ok <КОД>`:

```
Чтобы отправить ровно это, ответь: ok 039CD8
> ok 039CD8
```

- Ответы «да» или «давай» не принимаются, нужен именно код. Если план поменяли после аппрува, меняется и код, и отправка блокируется.
- Пока идёт сессия pr-assistant, прямые `gh pr comment/review/merge`, `gh api` с POST/PATCH/PUT/DELETE, GraphQL-мутации и `git push` запрещены.
- Хук отвечает `deny`, а такое решение действует и в режиме `bypassPermissions`.
- В коммитах, ответах и комментариях нет следов ассистента: ни `Co-Authored-By`, ни «Generated with Claude», ни упоминаний Claude или ИИ. Коммит с такой строкой хук отклоняет.
- Другие сессии Claude Code хук не трогает.
- Комментарии публикуются ревью `COMMENT`; изменения плагин не запрашивает. Approve он ставит только PR без замечаний, только если ты выбрал его в плане и только если с ревью в PR не появилось новых коммитов. Треды он не резолвит: это решает ревьюер.

Ограничение: хук проверяет текст команд. Он защищает от случайной отправки, а не от модели, которая целенаправленно ищет обход. Например, он не остановит свой скрипт, который сам вызывает `gh`. Скиллы прямо запрещают так делать.

## Где лежат файлы

| Что | Где |
|---|---|
| Клоны репозиториев | папка, которую плагин спросит при первом запуске |
| Worktree для PR | `<папка клонов>/.pr-worktrees/<repo>-<N>` |
| Результаты ревью, планы, состояние хука | `~/.cache/pr-assistant/` (`PR_ASSISTANT_STATE_DIR`) |

При первом запуске плагин спрашивает, где лежат твои репозитории, и запоминает ответ в `~/.config/pr-assistant/config.json`. Если нужный репозиторий там уже склонирован (`<папка>/<repo>` или `<папка>/<owner>/<repo>`, и `origin` указывает на тот же репозиторий GitHub), плагин работает с этим клоном. Если нет, клонирует его туда сам. Папку можно поменять командой `config.py set repos_dir <path>` или переменной `PR_ASSISTANT_REPOS_DIR` в `~/.claude/settings.json`:

```json
{ "env": { "PR_ASSISTANT_REPOS_DIR": "/path/to/repos" } }
```

Твою рабочую копию плагин не трогает: не переключает ветки и не касается незакоммиченных изменений. В клоне он только делает `fetch` и добавляет worktree. Ревью идёт в отдельном worktree на голове PR. Правки к своим PR делаются в worktree на ветке `pr-assistant/<N>` и пушатся в ветку PR fast-forward, без `--force`.

## Как устроено ревью

`/code-review` запускается отдельным процессом `claude -p "/code-review medium <merge-base>...<head>"` в worktree. У этого процесса:

- нет прав на правку файлов, `gh`, `git push`, веб и MCP-серверы;
- нет GitHub-токена в окружении;
- есть только чтение кода и git.

Результат кэшируется по head SHA: если PR с прошлого раза не обновлялся, повторный запуск ничего не тратит. Уровень можно передать аргументом: `/pr-assistant:review-requests high`. По умолчанию `medium`: на моих замерах он давал мало шума.

Ревью расходует лимиты подписки Claude. На небольшом PR это 1–2 минуты и 150–700K токенов, на крупном до 3,6M. По умолчанию одновременно идут 2 ревью, число задаётся аргументом `jobs=N` (не больше 4): `/pr-assistant:review-requests jobs=3`. Токенов на PR параллельность не экономит: тот же лимит просто расходуется быстрее. Если упрёшься в лимит, новые ревью не запускаются, уже идущие доделываются, и прогон покажет, что осталось.

## Повторное ревью

Перед каждым ревью плагин смотрит, что уже сказано в PR, и выбирает режим:

- ты этот PR ещё не комментировал — обычное ревью;
- ты его уже ревьюил и после этого появились коммиты — ревьюятся только изменения после твоего последнего ревью, а в отчёт попадают только подтверждённые блокеры 🔴. Если после твоего ревью в ветку влили `main` или историю переписали, ревьюится весь PR, но фильтр остаётся тем же;
- новых коммитов с твоего ревью нет или автор ещё не ответил на какой-то твой тред — ревью не запускается, PR попадает в список пропущенных с причиной. Тред, на который автор ответил, считается закрытым, даже если его не зарезолвили.

Находка, которая уже есть в любом комментарии к PR (твоём или чужом, в закрытом треде или открытом), в отчёт не попадает. Так плагин не повторяет сказанное и не заводит бесконечные круги ревью с новыми мелочами. Пропущенный PR можно проверить принудительно: «перепроверь #65».

## Связанные PR

Одна задача часто задевает несколько репозиториев. PR считаются одной задачей, если у них общий ключ тикета в заголовке или ветке (`PROJ-1234`), одинаковое имя ветки (кроме `main`, `develop`, `release/*` и подобных) или один PR ссылается на другой в описании. В отчёте такие PR идут одним блоком.

Когда все PR группы отревьюены по отдельности, запускается ещё один read-only проход по группе целиком (`cross-review.sh`). Он ищет только то, что не видно внутри одного PR: несовпадение полей событий и DTO между продюсером и консьюмером, миграции против entity и DAO, имена конфиг-свойств, версии общей библиотеки, порядок деплоя. Этот проход получает диффы файлами и доступ на чтение к worktree всех PR группы; shell, правки, `gh`, веб и MCP ему недоступны. Результат кэшируется по набору head SHA группы.

## Установка

Нужны `gh` (с `gh auth login`), `git`, `python3` и Claude Code.

```
/plugin marketplace add Ixxxeon/pr-assistant
/plugin install pr-assistant@pr-assistant
```

Для разработки плагин можно подключить из локальной папки: `/plugin marketplace add /path/to/pr-assistant`.

Если у тебя установлен скилл `writing-plainly`, комментарии проходят через него: так они получаются короче и без канцелярита. Без него плагин тоже работает.

## Структура

```
.claude-plugin/        манифесты плагина и marketplace
hooks/hooks.json       хуки UserPromptSubmit и PreToolUse(Bash) → scripts/guard.py
skills/review-requests SKILL.md первой команды
skills/my-prs          SKILL.md второй команды
scripts/
  list-review-requests.sh  PR, где ревью запрошено лично у тебя
  list-my-prs.sh           твои открытые PR
  pr-status.py             аппрувы, готовность к мерджу, треды без ответа
  prepare-worktree.sh      клон + worktree (review: detached, own: ветка pr-assistant/<N>)
  group-prs.py             группировка PR по задаче
  review-batch.py          параллельный прогон ревью и проверок групп
  review-history.py        что уже сказано в PR, режим ревью
  review-pr.sh             worktree + ревью + кэш одного PR
  run-code-review.sh       read-only запуск /code-review
  cross-review.sh          read-only проверка группы PR между собой
  check-claude-output.py   разбор результата claude -p, признак лимита
  config.py                папка клонов: чтение, запись, поиск клона
  locked.py                блокировка клона репозитория на время fetch/worktree
  plan.py                  план записей в GitHub и код аппрува
  post.py                  отправка одобренного плана
  guard.py                 хук-предохранитель
```
